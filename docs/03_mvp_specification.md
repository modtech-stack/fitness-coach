# AI Fitness Trainer
# MVP Specification v1.0


# 1. Цель MVP

Создать первую рабочую версию AI Fitness Trainer для двух пользователей:

- Борис;
- Алёна.

MVP должен проверить гипотезу:

"Может ли AI помочь человеку создать, выполнить и адаптировать персональную тренировочную программу лучше, чем обычная таблица и чат?"


---

# 2. Пользовательские роли


## User

Пользователь:

- создаёт профиль;
- задаёт цели;
- указывает ограничения;
- получает программу;
- выполняет тренировки;
- получает рекомендации.


## Program Reviewer

В MVP:

Борис.

Функции:

- проверяет программу;
- обсуждает её с GPT;
- подтверждает или изменяет.


В будущем:

- тренер.


---

# 3. Основные пользовательские сценарии


## Сценарий 1.
Создание профиля


Пользователь вводит:

- возраст;
- пол;
- рост;
- вес;
- опыт тренировок;
- цель;
- доступное время;
- оборудование;
- ограничения;
- предпочтения.


Результат:

Создан профиль пользователя.


---

## Сценарий 2.
Создание тренировочной программы


GPT получает:

- профиль;
- цель;
- ограничения.


Создаёт:


### Макроцикл

Например:

12 недель.


### Мезоциклы

Например:

Фаза 1:
адаптация

Фаза 2:
прогрессия

Фаза 3:
закрепление


### Микроциклы

Недельный план:

- дни тренировок;
- упражнения;
- объём;
- интенсивность;
- прогрессия.


Статус:

Draft.


---

## Сценарий 3.
Аудит программы


Reviewer проверяет:

- соответствие цели;
- объём;
- баланс мышечных групп;
- последовательность нагрузок;
- восстановление;
- реалистичность.


## Жизненный цикл программы


Training Program имеет состояния:


Draft

↓

Under Review

↓

Approved

↓

Active

↓

Needs Adjustment

↓

Updated


Программа не является статичным документом.

Она может изменяться на основании:

- результатов выполнения;
- обратной связи пользователя;
- ошибок в первоначальном планировании;
- изменений целей или ограничений.

---

## Сценарий 4.
Выполнение тренировки


Пользователь видит:

Сегодня:

- тип тренировки;
- упражнения;
- подходы;
- повторения;
- цель нагрузки.


После тренировки:

записывает:

- фактический вес;
- повторения;
- RPE;
- комментарии.


---

## Сценарий 5.
Ежедневная адаптация


Система анализирует:

- сон;
- самочувствие;
- боль;
- болезнь;
- ЧСС покоя;
- предыдущую нагрузку.


Training Engine выдаёт:

- выполнить план;
- снизить нагрузку;
- заменить тренировку;
- восстановиться.

## Сценарий 6.
Корректировка программы


После выполнения тренировок система собирает:

- фактический объём;
- RPE;
- боли;
- самочувствие;
- комментарии пользователя;
- результаты.


Если обнаружены проблемы:

- чрезмерный объём;
- недостаточная нагрузка;
- плохое восстановление;
- несовместимость тренировок;


то создаётся предложение изменить программу.


Изменение проходит:

анализ → предложение → подтверждение → новая версия программы.

---

# 4. Что входит в MVP


Обязательно:

## Пользователь

✓ профиль

✓ цели

✓ ограничения


## Program Builder

✓ генерация программы GPT

✓ макроцикл

✓ мезоциклы

✓ микроциклы


## Program Review

✓ просмотр программы;

✓ обсуждение программы с GPT;

✓ выявление ошибок и несостыковок;

✓ комментарии Reviewer;

✓ изменение программы;

✓ утверждение финальной версии.


## Training Log

✓ плановая тренировка

✓ фактическая тренировка

✓ результаты


## Training Engine v1

✓ сон

✓ самочувствие

✓ болезнь

✓ боль

✓ корректировка нагрузки


---

# 5. Что НЕ входит в MVP


Не делаем:

- мобильное приложение;
- социальные функции;
- магазин программ;
- автоматическую замену тренера;
- сложный ML;
- прогноз травм;
- автоматическую сборку программы из библиотеки тренировочных блоков;
- полноценную систему Training Blocks Library.

# 7. Критерий успеха MVP


MVP успешен, если:

- Борис и Алёна используют приложение минимум 8 недель;
- создают программы;
- выполняют тренировки;
- получают полезные корректировки;
- находят ошибки в логике программ.

# 8. Ограничения MVP


MVP создаётся как персональный инструмент.

Не оптимизируем пока:

- масштабирование на тысячи пользователей;
- коммерческую модель;
- маркетплейс тренеров;
- сложную аналитику.


Главная задача:

проверить качество цикла:

создание программы → выполнение → адаптация → улучшение.
