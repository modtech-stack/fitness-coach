# AI Fitness Trainer
# Codex Development Instructions v1.0


# 1. Роль

Ты являешься ведущим AI-разработчиком проекта AI Fitness Trainer.

Твоя задача — создать первую рабочую версию приложения на основе существующей документации проекта.

Перед началом разработки изучи:

- docs/01_product_vision.md
- docs/02_core_model.md
- docs/03_mvp_specification.md
- docs/DECISIONS.md
- knowledge/training/training_engine_principles_v0.9.md


---

# 2. Главная цель разработки

Создать MVP приложения AI Fitness Trainer.

Главный критерий:

Пользователь должен пройти полный вертикальный сценарий:


Создание профиля

↓

Определение цели

↓

Генерация тренировочной программы

↓

Просмотр программы

↓

Выполнение тренировки

↓

Ввод результата

↓

Получение рекомендации


---

# 3. Принцип разработки

Не создавать сразу сложную платформу.

Сначала реализовать минимальный работающий сценарий.

После появления работающего MVP:

- улучшать архитектуру;
- добавлять интеграции;
- расширять функциональность.


---

# 4. Первый вертикальный срез MVP


Реализовать:


## Пользователь

Создание профиля:

- имя;
- возраст;
- пол;
- рост;
- вес;
- тренировочный опыт;
- цель.


---

## Цель

Поддержать:

- рекомпозиция;
- снижение веса;
- набор массы;
- выносливость.


---

## Program Builder

Создать первый вариант генерации программы.

GPT должен формировать:


12-недельную программу:

- макроцикл;
- мезоциклы;
- микроциклы;
- недельные тренировки.


Программа должна сохраняться в базе данных.


---

## Program Review

Добавить статус:


Draft

Approved


Пользователь может:

- просмотреть программу;
- подтвердить.


---

## Training Log

Пользователь может:

- открыть сегодняшнюю тренировку;
- отметить выполнение;
- добавить:
    - вес;
    - повторения;
    - RPE;
    - комментарий.


---

## Training Engine v1

Реализовать минимальный набор правил:


Если:

сон < 6 часов

или плохое самочувствие

или болезнь


то:

снизить нагрузку или заменить тренировку.


---

# 5. Технические решения


Если нет причин изменить архитектуру:

использовать:


Frontend:

Next.js + TypeScript


Backend:

Supabase


Database:

PostgreSQL


AI:

OpenAI API


---

# 6. Работа с архитектурой


Перед изменением архитектурных решений:

1. Объясни проблему.
2. Предложи варианты.
3. Зафиксируй решение в docs/DECISIONS.md.


Не переписывай фундаментальные решения без обсуждения.


---

# 7. Кодинг-подход


Ты должен:

- писать простой поддерживаемый код;
- избегать преждевременного усложнения;
- создавать понятные компоненты;
- добавлять документацию;
- добавлять тесты для критической логики.


---

# 8. Самопроверка


После реализации каждого этапа:

Проверь сценарий глазами пользователя:

"Я впервые открыл приложение. Что я могу сделать?"


Исправь:

- ошибки;
- непонятные места;
- отсутствующие шаги.


---

# 9. Первый результат


Не пытайся создать весь продукт сразу.

Первый milestone:


Рабочее приложение, где:

1. Пользователь создаёт профиль.
2. GPT создаёт программу.
3. Программа сохраняется.
4. Пользователь видит тренировку.
5. Пользователь может отметить выполнение.


После этого переходить к расширению.
